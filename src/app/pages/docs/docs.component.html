Documentation

IT Kamianets 3D Engine is a set of reusable packages for building 3D applications and games. This section explains how the pieces fit together and how to install them.

Where to start

  • Architecture: the three layers and how scenes flow between Unity and the shared schema.
  • Installation: Unity requirements and the Package Manager URL of every package.
  • Packages: one page per package with its current state and roadmap.
  • Constructors: planned starting points for each camera and gameplay style.

Project status

The core packages are in early development and the scene schema has a first version. Constructors and game generation are planned and have no repositories yet. Each package page states what exists today and what does not.

All source code lives in the IT-Kamianets GitHub organization.

Installation

The Unity packages are installed through the Unity Package Manager from their Git repositories.

Requirements

  • Unity 6000.6
  • Git installed, so Unity can fetch packages by URL
  • For room scanning with 3d-unity-spatial: the Meta XR MR Utility Kit (com.meta.xr.mrutilitykit) in your project

Steps

  1. In Unity, open Window > Package Manager.
  2. Choose + > Add package from git URL.
  3. Paste the URL of the package from the table below.

Dependencies between engine packages are declared in each package.json. Install 3d-unity-core first, and add the package you need.

Architecture

The ecosystem is split into three layers, and scenes are kept in an engine-independent format.

Layers

  1. Core packages (3d-*): shared engine functionality such as scenes, assets, interaction, XR, and spatial data.
  2. Constructors (3d-constructor-*): a starting architecture for one type of game, built on the core packages.
  3. Game-specific packages (game-<name>-*): the rules, content, and assets of one game.

Scenes and the schema

3d-scene-schema is the source of truth for a scene. Unity is not the permanent owner of scene data:

Scene Schema → Unity Scene → Scene Changes → Scene Schema

3d-unity-scene converts between the two. 3d-unity-xr handles how users interact through XR hardware, while 3d-unity-spatial understands the physical room and turns it into scene data.

Package dependencies

Packages are grouped by dependency depth. Each package depends only on packages from earlier columns, as declared in its package.json.

Principles

  • Keep core packages reusable and product-independent.
  • Keep constructors focused on reusable gameplay architecture.
  • Keep game-specific logic outside the framework.
  • Prefer shared scene and asset structures between engines.
  • Let constructors compose existing packages instead of duplicating them.
  • Make generated projects easy to understand, modify, and extend.
